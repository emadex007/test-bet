# Emadex Starter

*The base for every Emadex Creations client website.*

One codebase, any business. Pick an industry, fill in the client's details, deploy. Every colour, word, page and feature is then editable from the client's own dashboard. Runs free on Cloudflare (Workers, D1, R2).

Built on **TanStack Start + Cloudflare Workers + D1 + R2 + Tailwind v4**, from the Jo-pearl Home Maker build.

**New client? Read [TEMPLATE.md](TEMPLATE.md).** It takes about 15 minutes from copy to a live link. Use [CLIENT-BRIEF.md](CLIENT-BRIEF.md) to collect what you need from the client first.

## What every site gets

- Public site: home, about, services, portfolio or property listings (a page and gallery per item), booking, request form with photo uploads, contact, FAQs
- Live chat (with WhatsApp) answered from the dashboard
- Quotation builder: send quotes by WhatsApp or email; clients view, print and accept online
- Testimonials slider and clients & partners logo strip
- Dashboard with logins: inbox, chat, quotations, portfolio/listings, services, testimonials, client logos, FAQs, site settings, staff, backups
- **Feature switches**: turn off booking, quotes, portfolio, services, FAQs, testimonials or logos for businesses that don't need them
- **Words & forms**: rename "Projects" to "Properties", "Cakes", "Events"…, and change every question on the request and booking forms
- **Layout styles** (Site settings → Layout): 5 overall feels (elegant, bold, modern, playful, minimal), 4 headers, 4 home banners (full photo, split, centred, photo slider), 4 services styles, 3 portfolio card styles, 3 testimonial styles, 3 footers, and drag-free reordering of home sections. Each industry pack starts with its own combination, so sites don't look alike
- Weekly automatic database backups, sitemap, branded emails

### Industry home designs and dashboard pages

Some packs have their **own home page design** (`src/homes/<id>.tsx`) and **their own dashboard pages** (for betting: Matches & odds, Casino games, Promotions; for crypto: Coins & markets). The dashboard menu also hides standard pages the industry doesn't use and renames others (e.g. "Agent applications"). Site settings → Layout → **Home page design** switches back to the standard home at any time.

**Betting and crypto run in DEMO mode** by default: a "Demo" bar shows fake money (kept in the visitor's browser) so clients can click around, place bets and make trades. In Site settings → **Betting / trading**, switch to **link** mode and add the client's real licensed platform address: "Place bet", "Play" and "Buy/Sell" then send visitors there. The website itself never takes real bets or holds real money.

A pack is one file in `src/packs/` (text, colours, form questions, switches) and its sample content in `packs/<id>/seed.sql` (generated by `scripts/build-seeds.py`). See TEMPLATE.md → Adding a new industry.

**Before launch, check the industry notes:** betting sites must show the client's real licence details (footer text), and finance, crypto and clinic sites keep their safety wording (no PINs or seed phrases, no promised returns, emergencies go to a hospital).

## First run on your laptop (Windows)

```powershell
cd C:\Users\LENOVO\Documents\GitHub\emadex-starter
nvm use 22
npm install
npm run new-client            # pick the industry and enter the client's details

npx wrangler d1 create emadex_starter_db       # paste the database_id into wrangler.toml
npx wrangler r2 bucket create emadex-starter-media
Set-Content -Path .dev.vars -Value "ADMIN_SETUP_CODE=pick-a-long-secret-code" -Encoding ascii
npm run db:migrate:local
npm run dev                   # http://localhost:3000, dashboard at /admin
```

(After `npm run new-client`, the database and bucket names change to the client's; it prints the exact commands.)

## Admin dashboard

The dashboard lives at **/admin**. The first time, you create the owner account with the setup code, so nobody else can claim the dashboard on a fresh deploy. Local and live are separate databases, so you create the owner once locally and once on the live site. The owner can add staff logins under **Staff & account**.

### Quotations

Inbox → open a request → **Create quotation** (client details are filled in), or Quotations → **New quotation**. Add items, an optional discount and VAT, check the valid-until date, then **Create quotation**. Send it with **Send on WhatsApp** or **Send by email** (needs Resend). The client gets a private link (`/q/...`) where they can view, print or save as PDF, and accept.

### Live chat

Visitors chat from the bubble at the bottom-right of the site. Replies happen in **Live chat** in the dashboard. While anyone has the dashboard open, the chat shows "Online now"; otherwise visitors see the away message from Site settings → Live chat.

### Optional: email notifications (Resend)

```powershell
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put ADMIN_NOTIFY_EMAIL   # where new bookings/requests/messages are sent
```

Until a domain is verified in Resend, emails send from `onboarding@resend.dev`. After verifying, add `RESEND_FROM = "Business Name <hello@theirdomain.com>"` under `[vars]` in wrangler.toml. For local dev, put the same keys in `.dev.vars` (git-ignored).

### Optional: receive emails into the dashboard

Once the client's domain is on Cloudflare: **Email → Email Routing → Routing rules → Send to a Worker → (the Worker name)**. Emails land in the dashboard inbox.

## Where things live

| Path | What |
|---|---|
| `src/business.ts` | The client's name, tagline, email, phone, city (written by `npm run new-client`) |
| `src/packs/` | Industry packs; `active.ts` says which one this site uses |
| `packs/<id>/seed.sql` | Each pack's sample content (copied to `migrations/0100_sample_content.sql`) |
| `src/lib/site-defaults.ts` | Every editable setting, the neutral defaults, and how pack + client are combined |
| `src/lib/features.ts` | Feature switches, which pages they control, price formatting |
| `src/lib/layout.ts`, `src/components/Hero.tsx`, `HomeServices.tsx`, `Header.tsx`, `Footer.tsx` | Layout styles for each section |
| `src/components/admin/settings-schema.ts` | The Site settings editor: add a field there and it shows up in the dashboard |
| `src/server/db.ts` | D1 queries, email notifications |
| `src/lib/api.ts` | Server functions used by pages (reads + form submissions) |
| `src/server.ts` | Worker entry: `/media/*` from R2, uploads, `/robots.txt`, `/sitemap.xml`, inbound email, backups |
| `src/routes/` | Pages: `/`, `/about`, `/services`, `/portfolio`, `/portfolio/$slug`, `/book`, `/quote`, `/contact`, `/q/$token`, `/admin/*` |
| `src/components/` | Header, footer, cards (portfolio and property), lightbox, chat, forms |
| `src/lib/admin-api.ts` | Dashboard server functions (every one checks the login session) |
| `src/lib/quotes-api.ts`, `src/lib/chat-api.ts` | Quotations and live chat |
| `migrations/` | D1 schema (0001 to 0005) + sample content (0100) |
| `scripts/new-client.mjs` | Sets the project up for a new client |
| `scripts/build-seeds.py` | Regenerates the general and real-estate sample content |
